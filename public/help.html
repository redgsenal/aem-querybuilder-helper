AEM Query Builder — Help

Reference guide for fields, node types, properties, and common search combinations.

Fields
Field Query Parameter Description Example
Domain internal only Selects which AEM environment to query. Not forwarded to AEM — used by the proxy to pick the correct host and credentials. Local, SIT1
Path path Restricts results to nodes under this JCR path. The query searches all descendants unless you add path.exact=true. /content/bpi/ph/en
Node Type type Filters by JCR primary node type. Only nodes of exactly this type (or a subtype) are returned. cq:Page
Property property The JCR property path to filter on, relative to each result node. Use slash notation for child nodes. jcr:content/cq:template
Property Value property.value The value the property must match. Supports wildcards (*) when property.operation=like is set. Partial matches use bpi/components/ style. /conf/bpi/settings/wcm/templates/article-page
Limit p.limit Maximum number of results to return. Use -1 to return all (use carefully on large repos). 100, -1
Node Types
Node Type What it represents Common use
cq:Page A page node in the content tree. Every AEM page is a cq:Page node. Its content lives in a child jcr:content node. Find pages by template, tag, or title
cq:PageContent The jcr:content node of a page. Holds all page properties (template, title, tags, replication status, etc.). Query page properties directly without the jcr:content/ prefix
dam:Asset A file/asset in the DAM (Digital Asset Manager). Covers images, PDFs, videos, and other uploaded files. Find assets by name, type, or metadata
nt:unstructured A generic JCR node with no fixed schema. Most AEM component nodes (placed on a page) are of this type. Find placed component instances by sling:resourceType
cq:Component A component definition node under /apps. Not content — this is the component blueprint. List all registered components in an app
cq:Template A page template definition under /conf or /apps. List available templates for a site
rep:User A user account node in the AEM repository (Jackrabbit/Oak security layer). Find or audit user accounts
Common Properties
Property What it filters Example value
jcr:content/cq:template The template used to create a page. Used with cq:Page node type. /conf/bpi/settings/wcm/templates/article-page
jcr:content/sling:resourceType The component type that renders a page's jcr:content node (i.e. the page component). bpi/components/custom/pages/bpiPhPage
sling:resourceType The component type of the node itself. Used with nt:unstructured to find placed component instances on pages. bpi/components/herobanner
jcr:content/jcr:title The title of a page as set in page properties. Home, About Us
jcr:content/cq:tags Tags applied to a page. Values use the tag namespace format. bpi:segment/retail
jcr:content/jcr:lastModifiedBy The AEM user ID who last modified the page. admin, zip-rssenal@bpi.com.ph
jcr:content/cq:lastReplicationAction The last publish/unpublish action performed on a page. Activate, Deactivate
jcr:primaryType The primary node type of the node itself. Useful for filtering within mixed-type results. cq:Page, nt:unstructured

About partial matches

By default AEM Query Builder uses an exact equals match on property values. To do a partial/contains match (e.g. find all components whose resourceType starts with bpi/components/), the underlying API requires adding property.operation=like with a % wildcard — this UI currently sends an exact match. For partial searches, use the Raw JSON tab to inspect what was returned, or query AEM's CRXDE query tool directly with LIKE syntax.

Each example below shows the exact field values to enter in the query builder. The Query String shows what gets sent to AEM's /bin/querybuilder.json.

🔧 Finding Component Instances

Find all places a specific component has been placed on pages.

Tips
  • Use Limit = -1 only on narrow, well-scoped paths — returning all results on a broad path can be very slow.
  • The Path and Property Value fields remember your previous entries — click into the field to see history.
  • Switch the Domain dropdown before running to query Local or SIT1 without changing anything else.
  • Use the Raw JSON tab to see the full AEM response including total count, offset, and all node properties returned.
  • The Sites URL column in results opens the page directly in the AEM page editor for that environment.
  • The jcr:content/ prefix is needed when the property lives on the page's content node, not the page node itself. When using cq:PageContent as node type, drop the prefix.
